# Screenshot Workflow

Support manual, assisted, and automated capture; assisted is the recommended default.

Each screenshot task records an ID, page IDs, filename, locale policy, required flag, entry steps, preconditions, expected state, sensitive-content constraints, capture status, file mapping, review status, and notes.

Statuses are pending, captured, needs-retake, approved, not-applicable, and blocked. Formal writing starts only when required screenshots are approved or explicitly waived.

Never fabricate application screenshots. Use localized live interfaces for each locale that requires them. Preserve originals; create annotated copies separately. Do not silently overwrite existing images. Pause for authentication, licenses, customer data, ambiguous dialogs, destructive actions, or unexpected application state.
